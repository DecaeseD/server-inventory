# چک‌لیست تست دستی (علاوه بر تست‌های خودکار)

اجرای خودکار: `DJANGO_SETTINGS_MODULE=config.settings.test python manage.py test`  (۸۲ تست)
بعد از هر تست دستی: `python manage.py verify_ledger` ← باید `ledger OK` بدهد.

## ۱. سرور کامل + سخت‌افزار (برای هر عملیات سرور تکرار شود)
عملیات‌ها: خرید، افزایش، برگشت از دیتاسنتر، برگشت از تعمیر، ارسال به دیتاسنتر، ارسال به تعمیر، انتقال، خروج/مصرف، کاهش
- [ ] روی قلم سرور دکمهٔ «افزودن سخت‌افزار» هست (به‌جز اسقاط) و با کلیک، قلم فرزند با سریال سرور پر می‌شود
- [ ] دکمه با ۰ یا ۲ سریال در قلم سرور هشدار می‌دهد
- [ ] قطعه از موجودی آزاد (نصب) و قطعهٔ جدید همراه سرور (ورود نصب‌شده) هر دو کار می‌کنند
- [ ] تغییر سریال سرور در قلم والد، سریال فرزندها را هم عوض می‌کند؛ حذف والد، فرزندها را هم حذف می‌کند
- [ ] بعد از تأیید: موجودی آزاد قطعه فقط یک‌بار کم شده؛ «نصب‌شده» اضافه شده؛ جمع همهٔ وضعیت‌ها ثابت است
- [ ] ارسال به دیتاسنتر ← برگشت: قطعات همراه سرور مانده‌اند و دوباره شمرده نمی‌شوند
- [ ] خروج/مصرف سرور: قطعاتش هم خارج می‌شوند (سند، خطوط «همراه سرور · خودکار» دارد)
- [ ] ابطال سندِ خروج: سرور و قطعاتش برمی‌گردند
- [ ] اسقاط سرور دارای قطعه: خطا می‌دهد (اول باید جدا شوند)

## ۲. اعتبارسنجی هنگام ثبت (نه فقط تأیید)
- [ ] سریال ناموجود (مثل taha وقتی فقط esfand هست) ← خطا با شمارهٔ قلم، سندی ساخته نمی‌شود
- [ ] سرور در دیتاسنتر ← ارسال دوباره به دیتاسنتر خطا بدهد؛ برگشت از انبار اشتباه هم خطا بدهد
- [ ] خروج بیشتر از موجودی (کالای تعدادی) خطا بدهد
- [ ] دو قلم در یک درخواست: خرید ۳ + خروج ۲ از همان کالا قبول شود
- [ ] ثبت دو درخواست وابسته پشت هم قبل از تأیید اولی (مثلاً خرید سرور، بعد ارسالش) ← قبول نمی‌شود (رفتار عمدی)
- [ ] بین ثبت و تأیید، موجودی را با درخواست دیگر مصرف کن ← تأیید باید خطا بدهد و سند pending بماند

## ۳. صفحهٔ کالا (/items/<id>/)
- [ ] تک‌تک نمونه‌ها دیده می‌شوند، حتی کالای «تعدادی» (کد داخلی `<شناسه کالا>-<شماره>`)
- [ ] انتخاب چند رم نصب‌شده ← «جدا کردن» ← درخواست pending ← تأیید ← می‌روند موجودی آزاد
- [ ] «انتقال به سرور دیگر»: انبار واسط + سریال سرور مقصد
- [ ] «نصب روی سرور» برای نمونهٔ آزاد
- [ ] نمونهٔ آزاد را با «جدا کردن» انتخاب کن ← خطا
- [ ] کاربر بدون مجوز ثبت درخواست: چک‌باکس و نوار عملیات نمی‌بیند
- [ ] فیلتر وضعیت «خارج از سیستم» نمونه‌های مصرف‌شده را نشان می‌دهد

## ۴. هویت مستقل هر قطعه
- [ ] خرید ۵ CPU (تعدادی) ← ۵ نمونه با کد یکتا
- [ ] خروج ۲ عدد (بدون سریال) ← ۲ نمونهٔ مشخص «خارج» می‌شوند و در سند ثبت‌اند
- [ ] ابطال آن خروج ← همان نمونه‌ها برمی‌گردند (نمونهٔ جدید ساخته نمی‌شود)
- [ ] کالای تعدادی هنگام ورود سریال دستی نمی‌پذیرد؛ هنگام خروج کد داخلی می‌پذیرد
- [ ] موجودی قدیمیِ بدون نمونه (قبل از این نسخه) هنوز قابل مصرف است و در صفحهٔ کالا هشدار زرد دارد

## ۵. نقش‌ها و امنیت
- [ ] انباردار نمی‌تواند تأیید کند؛ ثبت‌کننده نمی‌تواند درخواست خودش را تأیید کند (مگر با تنظیمات)
- [ ] حسابدار بدون مجوز هیچ‌چیز نمی‌بیند؛ قیمت فقط با مجوز `view_prices`
- [ ] ثبت دوبارهٔ همان فرم (دابل‌کلیک / refresh) فقط یک سند می‌سازد
- [ ] سند کاربر دیگر در `/documents/<id>/` برای انباردار 404 است

## ۶. هم‌زمانی (فقط روی MySQL واقعی؛ SQLite قفل را نادیده می‌گیرد)
- [ ] دو مدیر هم‌زمان دو سند متعارض روی یک موجودی را تأیید کنند ← فقط یکی موفق شود
- [ ] تأیید هم‌زمان یک سند توسط دو نفر ← یکی خطا بگیرد
